# TipHUD — статический аудит подавления изображения

**Гейт BLOCKED.** Для Steam 1.09/build 12996889 и UE4SS `83330635`
отдельная настройка цвета корневого TipHUD доступна в отражении. Статика
не подтверждает, что она подавляет только экранные пиксели и сохраняет
заимствованный World-значок. Основа аудита `35f205adc96137051cd28c51bdaca07861bd8bb3`.

## Владельцы состояния и отрисовки

- `PlayerActionComponent+0x410` даёт выбранного владельца. `IIPInteractionSource`
  проверяет экранный компонент (`bVisible`, `bAddedToScreen`), состояние TipHUD
  и готовность исходного текста. `IIPOpenVisibility` и `IIPHintSource` проверяют
  `Visibility`, `RenderOpacity`, `bIsEnabled` и валидность нужных объектов.
  Корневой `ColorAndOpacity` в эти предикаты не входит. `CanShow` вызывает
  native parent и учитывает режим ввода. Blueprint Tick пишет `RenderOpacity`
  0/1, `SetupTipMessage2` поставляет локализованный текст, а отдельная ветка Tick
  обновляет `t` для прогресса удержания в материале Retainer.
- В TipHUD `CanvasPanel_0 → HorizontalBox_4 → CanvasPanel_6` содержит соседние
  ветки `TextBlock_89`, `RetainerBox_0 → ImageInteractAllowed` и
  `CanvasPanel_2 → ImageInteractNotAllowed`. `IIPHintSource` берёт MID через
  `GetEffectMaterial` и использует его для World-изображения. Замена текстуры,
  alpha материала или параметра `t` затрагивает заимствованный источник.
  [World-код и доказательства](../selected-owner-world/README.md),
  [статическая иерархия](../../../../docs/VERIFIED_RUNTIME.md).
- В UE4.27 `FWorldWidgetScreenLayer::AddComponent` передаёт `TakeWidget()`
  экранному слою Slate. `SWorldWidgetScreenLayer` помещает его в проецируемый
  `SConstraintCanvas`. Общий слой обслуживает и другие компоненты. Материальный
  `TintColorAndOpacity` у `UWidgetComponent` используется в World-маршруте,
  экранный путь не использует этот материал. Общего для текста и обоих значков
  отдельного финального композита на компоненте в проверенной цепочке нет.
  [WidgetComponent](https://github.com/AlexMercer-MA/UnrealEngine-4.27/blob/306a7e9f7fb53f14c2cb3bfd3854ad906710a17e/Engine/Source/Runtime/UMG/Private/Components/WidgetComponent.cpp#L57-L111).

## Точки вмешательства

| Точка | Влияние и решение |
| --- | --- |
| `Visibility` / `RenderOpacity` у корня или проверяемых потомков | Прямо ломает текущий readback. Tick также владеет `RenderOpacity`. Одной обратимой записи недостаточно для сохранения штатной семантики. |
| Screen layer, смена Space, удаление screen widget | Смена членства затрагивает `bAddedToScreen` и native путь. Вмешательство в общий слой затрагивает посторонний HUD. Смещение за экран меняет геометрию и может исключить Retainer из отрисовки. |
| Финальная поверхность `RetainerBox_0` | Только ветка разрешённого значка. Текст и locked-значок выводятся отдельно. Изменение общего MID также затрагивает World. |
| `UUserWidget::SetColorAndOpacity` на точном экземпляре TipHUD, исходный RGB и alpha 0 | Наиболее узкая точка для проверки. Отражённая сигнатура `void SetColorAndOpacity(FLinearColor)` есть в локальном UHT `UMG/Public/UserWidget.h`. UE4.27 сохраняет отдельный `ColorAndOpacity` и обновляет `MyGCWidget`. `SynchronizeProperties` может подключить `ColorAndOpacityDelegate`. В локальном экспорте TipHUD явного свойства/биндинга не найдено, отсутствие живой привязки или конкурирующего writer ещё предстоит подтвердить. Вызов и чтение значения через точный UE4SS для этого экземпляра не проверялись. [UserWidget](https://github.com/AlexMercer-MA/UnrealEngine-4.27/blob/306a7e9f7fb53f14c2cb3bfd3854ad906710a17e/Engine/Source/Runtime/UMG/Private/UserWidget.cpp#L279-L305). |

В проверенном исходнике `SRetainerWidget::OnPaint` создаёт контекст из
`InWidgetStyle` и передаёт его в `PaintRetainedContentImpl`. Этот контекст
идёт в `DrawInvalidationRoot`, а slow path передаёт `Context.WidgetStyle`
в `SCompoundWidget::OnPaint`. Финальная экранная поверхность Retainer
также умножается на tint контекста. Следовательно, корневой tint нельзя
считать изолированным от offscreen-захвата. Ненулевой старый кадр в RT
может временно скрыть проблему до следующего repaint. Из исходников нельзя
вывести, останется ли реальный World-значок свежим и видимым на этой сборке.
[SRetainerWidget](https://github.com/AlexMercer-MA/UnrealEngine-4.27/blob/306a7e9f7fb53f14c2cb3bfd3854ad906710a17e/Engine/Source/Runtime/UMG/Private/Slate/SRetainerWidget.cpp#L475-L666).

## Один следующий эксперимент

При отдельном разрешении использовать проверенный Selected-owner World как
контроль и отдельную временную исследовательскую надстройку. Один обычный
Open, одна подтверждённая пара owner/TipHUD, без обхода объектов и без
изменения общего MID. Сначала увидеть обе подсказки. После `SHOWN` и
визуального подтверждения World вручную включить короткое, ограниченное по
времени окно tint. `SHOWN` следует за `host:SetVisibility(3)` и подтверждает
команду game thread, поэтому сам по себе не разрешает автоматическое подавление.

1. Перед записью подтвердить доступность API, валидность и идентичность
   TipHUD, исходный цвет и отсутствие привязки/другого writer. Если это не
   удаётся, закончить без записи. Сопоставлять owner, native readback,
   локализованный текст и реальное изображение. Дать значку обновиться при
   обычной смене устройства ввода, если доступна, либо при штатной анимации
   удержания, если она безопасна в выбранном сценарии. Один статичный значок
   оставляет проверку обновления открытой.
2. В том же коротком окне принудительно скрыть только World-представление,
   пока Open штатно доступен. Восстановить исходный tint до скрытия World и
   наблюдать возврат Screen. Запись восстанавливается только для той же
   живой идентичности, пока текущее значение равно записанному тестом.
   Не перезаписывать цвет, если им уже завладел другой writer. STOP, истечение
   окна, потеря owner/World и ошибки должны идти через тот же путь восстановления.
3. Успех для Open: экранные пиксели исчезли, World-текст и значок видны и
   значок обновляется, native readback/owner и остальной HUD сохраняются,
   Screen возвращается при контролируемой потере World. Остановиться при
   blank/frozen hint, изменившемся readback, чужом writer или потере
   возможности точного восстановления. Восстановить tint и проверить его
   до выхода или смены карты. При разрушении объекта не писать через
   устаревший указатель.

Успех этого опыта оправдает проверку полноценного протокола восстановления.
Останутся прямой handoff, покадровый стык World/Screen, действие и remap,
другие действия/locked-ветка и живые переходы EndPlay/LoadMap. Для последних
нужно доказать безопасную возможность снять подавление до потери валидности,
если штатное изображение ещё необходимо. Отключение при закрытом процессе
не сохраняет tint экземпляра. Живое отключение потребовало бы доказанного
STOP до выгрузки.

Предполагаемая добавочная CPU-работа ограничена проверкой текущей пары на
существующем шаге и setter на границах, без новых обходов и пересозданий.
Setter может вызвать invalidation и повторную отрисовку Retainer. GPU/CPU
стоимость и задержка между видимыми кадрами остаются неизвестными.

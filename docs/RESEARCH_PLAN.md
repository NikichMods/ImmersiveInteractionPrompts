# Первое исследование — contextual prompts и письменность

**Вопрос:** где заканчивается цепочка рендеринга подсказок взаимодействия и какие оригинальные игровые глифы доступны? До доказательства — только исследование, production gate BLOCKED.

## Сначала принятые данные

Прочитать DevRules WORKING_RULES, ENGINEERING_RULES, GIT_WORKFLOW, CODEX_WORKFLOW, RUNTIME_INTEGRATION; root AGENTS/WORKFLOW/VERIFIED_RUNTIME; этот модуль; `NikichMods/Asterigos-Research/docs/RESEARCH_INDEX.md`. Сверить локальный checkout, branch/HEAD, изменения, игнорируемое окружение. Из соседних модов использовать только относящиеся к делу проверенные сведения (SoulsEnemyHUD, SubtitleSoftEdges, CombatHUD).

## Узкие доказательства

1. Найти через существующий локальный asset reader/метаданные UI точный widget/HTML owner подсказок; условия создания/обновления/скрытия и последний потребитель/писатель отображаемого текста.
2. Проследить native localized action и keyboard/gamepad glyph, включая переключение, не заменяя данные придуманными строками.
3. Проверить, единый ли owner у pick up/open/read/descend или есть разные типы UI.
4. Выявить доступные игровые fonts/atlases, включая возможно называемые Aphes: тип, путь, charset, допустимость рендера и есть ли настоящая таблица соответствий действий/слов. Отличать эстетические символы от проверенного языкового перевода.
5. Установить пересечения с установленными модами (особенно штатный UMG/Coherent HUD, SubtitleSoftEdges, SoulsEnemyHUD) и безопасные границы изменений.

Не принимать статическое имя объекта за доказательство real runtime-path. Отмечать факты, гипотезы, ограничения, точные источники/версию.

## Выбор после исследования

Сравнить реальные варианты: (а) узкое расширение native widget, (б) узкая правка host UI-ресурса, (в) отдельный overlay. Выбирать по сохранению реального input/localization/lifecycle, минимальности, совместимости, rollback и распространению host-owned assets. Пока механизм не принят.

Если статики недостаточно, подготовить **один** read-only runtime probe на конкретные события и состояния. Не запускать/завершать игру автоматически, не менять загруженные файлы и не применять hot reload; пользовательский прогон отдельно. Не добавлять диагностический код в production.
